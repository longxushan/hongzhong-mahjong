## 第一部分　项目定位与交付目标

### 1.1 产品是什么
1. 一款单机“红中麻将”H5：4 人对局，玩家 1 人 + 电脑 AI 3 人，无真人联网联机。
2. 现名“巢湖-金华红中”，历史曾用名“巢湖-红中麻将 / 半山红中”，改名只涉及标题三处，不影响逻辑。
3. 最高诉求：让 AI 充当“超级麻将高手师傅”，在打牌过程中持续教学，把牌理通过真实牌局教会玩家，而不是机械背口诀。

### 1.2 最终交付形态
1. 单文件 HTML5，零外部依赖：牌面 SVG、头像、样式、脚本全部内联，不请求任何网络资源。
2. 可直接双击用浏览器打开，也可部署到任意静态服务器、对象存储或子路径；因为资源全内联，放入子路径无需修改 base 路径。
3. 强制横屏：支持屏幕旋转锁定与全屏；手机、平板、车机自适应，窗口尺寸变化时按比例重排。
4. 支持生成可分享的在线访问链接（由文件交付平台产生，禁止手写伪造链接）。

### 1.3 复刻的硬性验收标准
1. 任意时刻全局牌数守恒，恒为 112；完整多局无 JavaScript 报错。
2. 胡牌判定严格，不允许“跳过多余牌”，模糊测试下零误判。
3. 出牌与教学推荐以向听数为主导，绝不拆成型面子（完整顺子/刻子）。
4. 听牌剩余数直接来自牌墙，不含别家手里、副露、弃牌。
5. 所有改动遵循“真实编辑 + 真实浏览器验证 + 真实交付”，禁止只改不验、禁止虚构链接。

## 第二部分　完整规则基线（锁定，不得漂移）

### 2.1 牌张与人数
1. 牌张：筒、条、万各 1～9，每种 4 张，共 108 张；红中 4 张；合计 112 张。无风牌、箭牌、花牌。
2. 4 人对局；庄家 14 张先出牌，闲家各 13 张；逆时针摸一打一。谁赢谁坐庄（2026-11-08 规则变更）：本局胡牌者下局当庄家；流局无人胡牌则庄家按序轮换。

### 2.2 红中（癞子万能牌）
3. 红中可代任意牌组的顺子、刻子、将、七对；可留可打。
4. 打出的红中，任何人不得碰、杠、胡。
5. 本人打出红中后胡牌按 2^n 翻倍：1 只 ×2、2 只 ×4、3 只 ×8、4 只 ×16；未胡不生效。
6. 红中硬规则：手中 ≥2 只红中且本局未打出过红中时，禁止胡牌，必须先打出一只红中（blockedByZRule）。

### 2.3 碰、杠
7. 不能吃；可碰，不限次数、最多 4 组。
8. 杠分明杠（放杠）、暗杠、补杠（弯杠）；杠后从牌墙尾部补牌。
9. 声明优先级：胡 > 杠 > 碰。

### 2.4 胡牌
10. 默认只能自摸、不可点炮；唯一例外是抢杠胡：手中有红中不可抢，无红中可抢别人补杠的牌；杠上开花保留。
11. 牌型：基本为 4 面子 + 1 将；特殊牌型为七对、全碰（碰碰胡）、清一色、杠上开花；全碰与七对互斥。

### 2.5 留底、流局与轮次
12. 牌墙保留最后 6 张不抓；进入留底即停止一切抓牌、杠、补杠，无人胡牌即流局；流局不翻码、只结杠分。
13. 8 局为一轮，顶栏显示第 N/8 局；一轮固定同桌 4 人、不换人，排行榜只统计这 4 人。
14. 第 8 局结束弹出最终榜单，可开始下一轮；开始下一轮清空累计分，重新从第 1/8 局计起。

### 2.6 计分五步（精确口径）
15. 第一步基础分：自摸 3，有红中减 1，有碰/杠减 1（只减一次），最低 1。
16. 第二步翻码：从牌墙头部翻牌，只认 1/5/9，每张 1 分。
    1) 软胡（有红中）翻 4 张，不保底，0～4 分。
    2) 硬胡（无红中）翻 6 张，0 张保底 6 分。
17. 第三步小计 = 基础分 + 翻码命中分。
18. 第四步番型连乘：全碰 ×4、七对 ×2（豪华七对 ×4）、清一色 ×2、杠上花 ×2、红中 2^n；全碰与七对互斥。
19. 第五步封顶 50。
20. 杠分（不占 50 封顶，可累计，流局也付）：
    1) 暗杠：其余三家各付 2，共 6。
    2) 补杠：三家各付 1，共 3。
    3) 放杠：点杠者单独付 2，共 2。
21. 赔付：自摸三家各按最终分全额付；抢杠由补杠者一人承担；每人总输赢 = 胡牌/翻码收付 + 全部杠分收付。

## 第三部分　牌面素材与内联工程

### 3.1 素材来源与协议
1. 牌面采用开源 FluffyStuff/riqi-mahjong-tiles，CC0 协议，SVG 格式，viewBox 为 300×400。
2. 实际需要 29 个 SVG：万 W1～W9、条 T1～T9、筒 B1～B9、红中 Z，外加牌背 BACK。
3. 原始 Back.svg 依赖 Inkscape 专属 path-effect，浏览器只渲染红块，故牌背放弃 SVG，改用纯 CSS 绘制（.tile-back）。

### 3.2 内联方式
4. 每个 SVG 以 URL 编码的 data URI 存进常量 TILES，形如 data:image/svg+xml;charset=utf-8,%3Csvg ... %3E，再由 tileDiv 引用。
5. URL 编码要点：`<` 编码为 %3C、`>` 为 %3E、`#` 为 %23、空格为 %20，引号在 URI 内统一用单引号避免冲突。
6. 头像同理：两套 JPEG 以 base64 data URI 内联（详见第八部分）。

### 3.3 关键牌面绘制规格
7. 普通数牌：使用开源 SVG 原样内联即可，保持 viewBox 0 0 300 400。
8. 万字牌（如需重绘）：两个 text，字体 font-family 为 "Kaiti SC, STKaiti, KaiTi, 楷体, AR PL UKai CN, AR PL KaitiM GB, serif"，bold，font-size 185；上字黑色（一～九）、下字红色（萬），stroke-width 6。
9. 红中：楷体 bold，font-size 270，x150 y305，颜色 #c0392b，stroke-width 10，只渲染“中”字。
10. 红中牌面不显示“癞”角标（该 CSS 角标已删除），仅在规则与教学文字中说明其万能牌属性。
11. 白玉底：牌面容器 .tile-photo 用浅色底；牌背 .tile-back 纯 CSS 实现，暗杠显示 1 张正面 + 3 张牌背。

## 第五部分　核心算法规格（复刻重点）

### 5.1 胡牌判定（严格，禁止容错跳牌）
1. standardWin：4 面子 + 1 将，递归 canFormN 判定，含红中代牌，不跨花色，不允许跳过多余牌。
2. allPongWin / pongN：全部为刻子，判定严格。
3. isSevenPairs：必须恰好 14 张、7 个对子，红中可配对；普通牌奇数计数种类 s 要求红中数 jk ≥ s 且 (jk-s) 为偶数。
4. 清一色：手牌含副露全部为同一花色。
5. 豪华七对：七对中某普通牌实体持有 4 张（算 2 对）即 deluxeSeven，番型 ×4；红中癞子凑的不算。
6. analyzeWin 汇总上述结果；rec 递归终止条件：left=0 时所有计数必须为 0 且红中恰好用完。

### 5.2 向听数引擎 calcShanten(handArr, melds)
7. 含义：-1 已胡、0 听牌、越大越远；标准形与七对分别计算后取最小。
8. 标准形：递归枚举刻子、顺子、对子（将/搭子）、两面与嵌张，公式为 向听 = 8 -（2×面子数 + 搭子数 + 将）；红中作万能牌，可补刻、顺、搭子、将或单独成块。
9. 七对（仅无副露可做）：实体牌 4 张算 2 对、2 张算 1 对，红中每只补 1 对，向听 = 6 - 对数。
10. 递归初始面子数等于副露组数，避免有副露时向听被算大。

### 5.3 统一高手出牌 masterDiscard(pl)
11. 对每个去重候选（红中除外）逐张模拟，计算 sh（打出后向听）、iw（立即听牌有效张）、dw（一进听有效进张）、bigFit（大牌契合度）。
12. 综合分 = -sh×100 + iw×2 + dw×0.2 + bigFit×big + 极小噪声；向听主导，再比听宽、进张。
13. 必须返回手牌中的真实牌对象（真实 uid），只读、无副作用。
14. 性格只通过 MASTER_PROFILE 的大牌偏好 big 与噪声 noise 区分，不改变精算水平。

### 5.4 碰杠精算 masterClaim
15. 方向保护：无副露做七对时碰杠一律拒绝；做清一色时别色牌不碰不杠。
16. 向听比较：模拟碰/杠并再出牌后的最小向听 after 与现状 before 比较。
    1) 碰：after>before 拒绝，after<before 接受，持平按性格概率。
    2) 杠：仅在 after 比 before 恶化超过 1 时拒绝，否则按概率（兼顾杠分与杠上花）。

### 5.5 教学诊断与推荐
17. handDiagnose：先识别并扣除成型刻子与顺子（completeMelds，完整面子不参与搭子分类），再统计红中、对子、刻子、两面/嵌张/边张、孤张、主花色、七对/清一色潜力、阶段（wall≥50 开局、≥25 中盘、否则残局）。
18. teachPick：完整逐张模拟，向听主导（向听→听宽→一进听进张→基础牌理 tileRoleRank），拆成型面子向听变大、自然排后，绝不拆完整顺子/刻子。
19. tileRemaining(id)：直接数 G.wall[head..tail] 中该牌张数，即牌墙真实可摸、不含别家手里；suitRemaining 对同花色求和。
20. 基础牌理 tileRoleRank 兜底分：幺九孤张 100、中张孤张 90、边张 80/85、嵌张 70、两面 60、对子 50、红中 40。
21. 支撑函数：countAppeared、countsOf、validTingIds（只统计 tileRemaining>0）、canReachTenpai、wouldWin、calcTing、recommendHandType、readOpponents。

### 5.6 出牌决策完整顺序 aiChooseDiscard
22. blockedByZRule 满足则先打红中；其次 shouldDumpSingleZ 命中按性格概率打红中；再走 masterDiscard；兜底打第一张非红中。
23. 单红中冒险 shouldDumpSingleZ 硬条件：恰好 1 只红中且未打出，并满足七对（普通对子≥4）/ 清一色（同花色≥9）/ 去掉红中即听三者之一；非大牌又不能即听则不冒险。

## 第六部分　流程状态机与牌数守恒

### 6.1 牌墙与发牌
1. buildWall：先按 112 张完整生成，再用 Fisher-Yates 洗牌；随机索引由 randInt 产生。
2. randInt：优先 crypto.getRandomValues（密码学安全）+ 拒绝采样消除取模偏差，老环境回退 Math.random。
3. newGame：13 轮每轮给 4 家各 1 张，再给庄家补第 14 张；庄家必须在发牌前先确定，第 14 张发给真庄家（历史 bug 是硬编码发给座位 0，已修）。
4. 牌墙全程不重排：对 wall 只有读取与 head++/tail--，没有任何 sort/shuffle 作用于 wall；sortTiles 只作用于手牌显示且返回新数组。

### 6.2 摸打与杠补
5. drawTile(pl,g)：g 为假从 G.wall[head++] 头部摸，g 为真从 G.wall[tail--] 尾部补杠；push 后 sortTiles，每次只加 1 张。
6. discardTile：按 uid 从 hand 移除并 push 到 discard。
7. 碰：doPeng 从手里移除 2 张，副露 push，再把别人打出的那张并入 tiles。
8. 杠：暗杠移除 4 张、明杠移除 3 张、补杠基于已有碰组；杠后从尾部补牌。
9. 等待出牌（awaiting 为 discard）时手里 14 张（刚摸），打出后 13 张。

### 6.3 主循环 run 与状态
10. run 为异步状态机，循环直到 G.over；human 玩家通过 waitHuman 等待，AI 通过 think 与 aiChooseDiscard 自动决策。
11. waitHuman 的 kind 取值：claim、gangself、zimo、qiang、discard、confirmZ；倒计时统一 TIMED，left=10，超时 humanRespond 由 AI 接管。
12. 碰/杠后的 continue 路径置 justClaim=true，跳过该次自摸判定，避免把点炮类动作误判为自摸。
13. 抢杠 checkQiangGang：有红中者不可抢，无红中且 wouldWin 才成立。

### 6.4 守恒铁律
14. 任意时刻：所有玩家 hand + 所有 melds.tiles + 所有 discard + 牌墙区间 = 112。
15. 每种牌（id）全场总数恒为 4；因此 tileRemaining 直接数牌墙与“4 减全场出现”在守恒时恒等。
16. 自动化测试必须用 G.awaiting 状态驱动，禁止用固定间隔轮询点击（会在异步间隙误点造成守恒假失败）。

## 第九部分　调试与验证方法（让智能体自检）

### 9.1 真实浏览器自动化环境
